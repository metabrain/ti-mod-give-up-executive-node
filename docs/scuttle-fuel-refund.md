# Scuttle propellant recovery

Native ScuttleCost requires ref_fleet.dockedAtHab, ref_hab.faction == ship.faction and AllowsShipConstruction(faction, checkInactives:true, checkUnderConstruction:false). Its ship construction call explicitly excludes propellant. TISpaceFleetState.ScuttleShips calls ScuttleCost for affordability and payment before destroying each ship.

The late-installed Harmony postfix adds the negative cost of remaining propellant to a copy of the native result. TISpaceShipTemplate.singlePropellantTankCost(faction, remainingTons /100) calls driveTemplate.GetPerTankPropellantMaterials(faction) and native resource-to-ton conversion. Native tanks are100tons and the helper accepts an uncapped fraction; this covers both partial and multiple tanks. No credit is paid during previews; native PayCost makes the sole actual payment. Repeated calls do not mutate the source result. Current faction conversion applies, rather than reconstructing historical refuelling costs.

The description postfix only changes ScuttleShipsOperation text. Disable removes owned patches. No gameplay types are patched until loadcycle100. Build uses installed game references; tests link the production refund adapter to stand-ins for the game types. Runtime scuttle confirmation, actual stockpile differences, multi-selection, mixed fuels and disable/re-enable remain in-game checks.

## Timed unloading (0.3.23)

Intercept ScuttleShipsOperation.ScuttleShipsFromFleet, after native action dispatch but before TISpaceFleetState.ScuttleShips. This avoids triggering TI Fleet Manager's reserve-scuttle bookkeeping before destruction. Validate every selected ship and native ActorCanPerformOperation, then calculate all durations before queuing. One native OperationData/time event per selected ship targets that ship; due dates are cumulative. No custom operation type, serializer extension, per-frame scan, upfront debit, or partial fuel transfer is introduced. Scheduling failures roll back added operations and do not fall through to instant destruction.

Duration = remaining tons / 100 * (daysToRefuelAPropellantTank + DockResupplySpeed officer adjustment) / ResupplySpeedDivisor. This uses continuous transfer at the native base rate, not PlanResupply's separate 0.01-day minimum per tank or its resupply queue. There is a one-second minimum per queued ship. Different fleets are not serialized against a shared station queue. Example: 2500 tons, 0.005 days per tank, divisor 2 gives 0.0625 days = 1.5 hours. Do not describe this as identical to a native refuel order's duration.

Scuttle's existing template is patched to delayed execution and blocking, with native cancellation allowed on request, departure and combat. Completion rechecks the due operation, original fleet membership, ownership/shipyard eligibility and combat before calling native ScuttleShips once. Canceled/stale events cannot pay. Native payment/destruction and other mods' fleet-scuttle hooks run at completion. No refund is due if cancellation or lost eligibility prevents completion. Fuel remains aboard until completion.

Native OperationData persists operationDataName, target, startDate and completionDate; OperationConfirmed creates the native TITimeEvent. These reuse the registered ScuttleShipsOperation template, so no mod-defined type must deserialize. With the mod absent, native ExecuteOperation is a no-op and the event expires without destroying the ship. Disabling cancels loaded scuttle operations while the timing hook is still active. Save/reload behavior is supported by inspected native code, not yet observed in-game.

Offline regression checks cover duration scaling, officer effects, invalid data, sequential orders, no upfront payment, duplicate confirmation/events, early events, cancellation, ownership/fleet changes, combat, and scheduling rollback. The installed assembly build also verifies API signatures. The selection header and ship cost rows show unloading time explicitly, avoiding the native cost formatter's erroneous division by 24 for sub-day durations with resource costs. Live UI layout and native cancellation/save-load remain acceptance checks.
